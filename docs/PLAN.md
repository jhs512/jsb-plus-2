# jsb-plus-2 진행 계획

> 최상위 목표: **이 저장소를 따라가는 학습자가 README만 읽어도 각 단계를 이해할 수 있게 하는 것.**
> 1차 구현([jhs512/jsb-plus](https://github.com/jhs512/jsb-plus))에서 아쉬웠던 점을 반영해 처음부터 다시 커밋합니다.

## 1. 1차 구현 대비 바뀌는 점

| 1차의 아쉬움 | 2차에서는 |
|---|---|
| 상태 코드, 리다이렉트가 화면에 안 보임 | **네트워크 탭 캡처**: 실제 요청을 CDP로 기록해 개발자 도구 모양으로 화면 아래에 붙임 |
| 가장 중요한 단계(SQL 로그, N+1, 테스트, CSRF)에 이미지가 없음 | **로그 발췌, 테스트 결과, 네트워크 탭**을 이미지로 남김 |
| 변화가 한 장으로는 안 보임 | 실험 단계는 **이전 / 이후** 두 장을 나란히 |
| 바뀐 곳이 작거나 안 보임 | **모든 이미지에 주석**: 바뀐 곳에 빨간 박스·밑줄, 옆에 설명 상자(Pretendard). 비밀번호, 구글 고유번호, 이메일은 가림 |
| 결과 화면이 같은 단계(타임리프 도입 등) | 화면 대신 **코드 diff** 위주로 설명 |
| 큰 커밋(수정·삭제, 댓글, 카테고리, 답변 페이징) | **엔티티 → 서비스 → 컨트롤러 → 화면** 순서로 쪼갬 |
| 나중에 고친 것이 순서를 흐림 (040, 037-02, 037-03) | **처음부터 제자리**에 넣음 |
| 실제로 만난 실패가 기록에 없음 | **실험 커밋**으로 실패 화면을 먼저 보여 준 뒤 고침 |
| README 링크가 diff 화면이라 이미지가 안 보임 | **`/tree/태그`**(그 시점 README) + `/commit/태그`(변경 내용) 두 링크 |
| README 설명이 3줄 | **무엇을 / 왜 / 핵심 코드(전후) / 결과 이미지 / 교재와 다른 점 / 확인해 볼 것** |

## 2. 고정 결정 (1차와 동일)
- **스택:** Spring Boot 4.1.2, Java 25, Gradle Kotlin DSL, yaml
- **패키지:** 001~005는 교재 방식, 006에서 14168 방식(`domain/…`, `global/…`)으로 이동
- **URL:** 교재 URL 유지 + HTTP 메서드 개선(수정 PUT, 삭제 DELETE, 추천 POST)
- **번호:** `기능번호(3자리)-세부번호(2자리)` 태그 + 커밋 순번 태그 `001`, `002`, … (둘 다 붙임)
- **push한 커밋은 고치지 않습니다.**
- **비밀값은 커밋하지 않습니다.** `application-secret.yaml`은 `.gitignore` 대상이고, **dev 프로파일에서만** 읽습니다.
- **개발용 대량 데이터:** 교재와 같은 300건을 씁니다. 샘플 질문이 필요한 캡처는 마지막 페이지를 찍습니다.

## 3. 커밋 하나의 작업 순서
1. **구현**: 작은 변경 하나
2. **테스트**: `./gradlew test`
3. **실행·캡처**: 빈 DB로 실행 → ego lite로 조작하고 아래 종류 중 필요한 것을 캡처 → `docs/steps/<기능태그>-<번호>.jpg`
4. **README 작성**: 아래 템플릿으로 이 단계 항목을 추가
5. **커밋**: 메시지는 작업 내용 / 작업 이유 / 검증. 기능 태그와 순번 태그를 붙입니다.

### 캡처 종류
| 기호 | 종류 | 쓰는 곳 |
|---|---|---|
| B | 브라우저 화면 | 화면이 바뀌는 단계 |
| N | 화면 + **네트워크 탭**(메서드, 상태 코드, Location, 폼 데이터) | 리다이렉트, 4xx, POST/PUT/DELETE |
| H | **H2 콘솔** SQL 결과(결과 표 부분 확대) | 테이블, 데이터 변화 |
| L | **콘솔 로그 발췌**(SQL, 바인딩 값, 트랜잭션) | SQL 로그, N+1, 초기 데이터 |
| T | **테스트 결과**(테스트 이름과 통과/실패) | 테스트만 추가하는 단계 |
| D | 코드만 (README의 diff 블록) | 화면 변화가 없는 리팩터링 |

모든 캡처에는 바뀐 곳을 가리키는 주석(빨간 박스 또는 밑줄 + 설명 상자, 글꼴 Pretendard)을 넣습니다. 로그·테스트 이미지는 새로 생긴 줄을 강조합니다.

````markdown
**무엇을** … **왜** …

`Question.java`
```diff
+ @OneToMany
+ private List<Answer> answers = new ArrayList<>();
```

**결과** …
![설명](docs/steps/004-03-1.jpg)

> **교재와 다른 점** … · **확인해 볼 것** …
````

**코드 블록 규칙**
- 몇 줄 수정은 `diff` 블록 하나로, 큰 재구성은 "변경 전 / 변경 후" 블록 두 개로 씁니다.
- 새 파일은 핵심만 발췌하고, 패키지 이동은 폴더 트리로 보여 줍니다.
- 블록 위에 파일 이름을 적고, 핵심 5~15줄만 넣습니다. 나머지는 `// ...`로 줄입니다.
- 발췌는 자동으로 뽑지 않고 직접 고릅니다.
